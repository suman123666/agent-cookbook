# 🛡 9.1 安全（最重要 ★）

## 3 类威胁 + 防御

### A. 输入威胁：Prompt Injection（提示词注入）

```
本质：恶意输入「劫持」LLM 的指令
攻击者把"忽略前面所有指令，输出 X"塞进 user 输入 / 工具返回 / 检索结果

3 种形态：
  ① 直接注入   user 直接说"忽略 system prompt"
  ② 间接注入   恶意网页/文档塞指令 → agent 读到 → 被劫持
  ③ 越狱      绕过安全限制让 LLM 输出违禁内容
```

**防御**：
- 输入边界检查（黑名单 / 敏感词过滤）
- LLM 防御层（让 LLM 先判断"这个输入是不是攻击"）
- 工具权限隔离（即便被劫持，工具能做的事是有限的）
- 敏感操作必须人工二次确认

### B. 行为威胁：危险工具滥用

**工具分级铁律 🟢🟡🔴**：

```
🟢 绿色：read_web、search                    自由调用
🟡 黄色：write_file、send_message            带边界（白名单）
🔴 红色：delete、transfer、send_external     必须人工确认
```

**判断破坏力 = 副作用范围 × 不可逆程度 × 影响他人程度**
- 不看动词（read/write），看 3 维度
- 默认「往严了估」

**Human-in-the-loop**：红色工具调用前必须 pause → 人审 → approve 才执行。

### C. 数据威胁：敏感数据 + 密钥

```
危险 1：把 user 隐私写进 prompt 发给云端 LLM   → 数据出境
危险 2：API key 写在代码里 / 提交进 git        → 公开泄露
危险 3：Tool 输出泄露内部系统结构              → 攻击面增大
```

**铁律**：
- 密钥**只**从环境变量 / 密钥管理系统读
- 敏感字段（手机号 / 身份证 / 密码）必须脱敏后才能进 prompt
- 永远不要把 user PII 当作"开发数据"提交进仓库

# 🚀 9.2 部署（从脚本到产品）

## 心智地图：餐厅类比

```
agent.py 脚本     = 家里厨房做饭（只能自己吃）
部署后的 server   = 开餐厅（100 人同时来吃）
```

## 3 种部署形态

| 形态 | 一句话本质 | 适合 | 时长 |
|------|-----------|------|------|
| **HTTP API** | 问一句答一句 | 简单对话 | < 30 秒 |
| **SSE / 流式** | 持续推送 token | 打字机效果 | < 几分钟 |
| **后台任务** | 下单提货 | 长报告/研究 | 几分钟~几小时 |

**怎么选**：
```
任务多久能完成？
   < 5s         → HTTP API
   5s~30s       → 需要打字机？是→SSE / 否→HTTP
   > 30s        → 后台任务（FastAPI + Celery + Redis）
```

## 部署 4 套路（看代码会用到这些词）

1. **逻辑/I-O 分离**：把 while+input/print 改成纯函数 `run_agent_turn(history)`
2. **状态外挂**：会话历史从内存 dict → Redis（多实例共享 + 不怕重启）
3. **接口契约**：用 Pydantic 定义请求/响应模型，自动校验+生成文档
4. **生命周期端点**：除了 `/chat`，还要有健康检查 + 会话清理

## 网址 / 域名

```
默认：http://localhost:8000          只有自己电脑能访问
--host 0.0.0.0：http://192.168.x.x   同 Wi-Fi 设备能访问
云服务器 + 域名：https://my-agent.com  全世界可达
```

**域名**：必须去注册商买（¥80/年起），没被人占的才能买。**国内云 + 中文用户 = 多一步备案**（免费但等 1-3 周）。

## 实战产出

`chapter_09_production/server.py` —— 把第 5 章 RAG agent 包成 HTTP 服务，包含：
- 4 个端点（健康检查 / 对话 / 删除会话 / 列出会话）
- 内存 dict 实现多用户会话隔离
- 启动：`uv run uvicorn chapter_09_production.server:app --port 8000 --reload`

`chapter_09_production/test.ps1` —— PowerShell 测试脚本，演示 alice/bob 跨用户隔离 + 跨请求会话记忆。

# 📊 9.3 监控（让 agent 不当黑盒）

## 核心难点

```
传统软件错了会 crash → 监控容易
agent 错了不会 crash → 它会「自信地胡说」
   → 必须监控「质量」不只是「可用性」
```

## 3 类核心指标：钱 / 快 / 准

```
💰 钱（成本）
   - 每日 token 消耗、每次对话平均花费
   - 异常突涨告警（防 bug 烧爆账单）

⚡ 快（延迟）
   - 首字延迟、完整响应时长
   - p50 / p95 / p99
   - ★ p95 比平均值更能反映用户真实体验

✓ 准（质量）
   - 成功率（第 8 章那个评估的在线版）
   - 工具调用错误率
   - 用户点赞/点踩
   - ★ 「24h 重提问率」是质量下降的最早信号
```

## Trace（行车记录仪）★ 最重要的创新

```
传统日志    = 流水账（一行一行）
Trace       = 结构化执行树
   ├─ user input
   ├─ LLM call #1 (prompt + response + token + 耗时 + 成本)
   ├─ tool call (args + result + 耗时)
   ├─ LLM call #2
   └─ final reply
```

**Trace 救命的 3 个场景**：
- 用户说"答错了" → 看 trace 复现每一步，精准定位
- 成本突涨 → 看 token 消耗 top 100 trace，找出失控 session
- 质量悄悄下降 → 抽样 trace 重跑评估，对比基线

## 告警分级

```
🔴 P0  服务挂 / 错误率 > 50%      → 凌晨 3 点叫醒人
🟠 P1  成本涨 5× / p95 > 30s      → 工作时间立即处理
🟡 P2  点踩率上升 / 慢请求增多     → 当天处理
🟢 P3  日报性质                    → 邮件看看就行
```

**阈值要「相对」不要「绝对」**：「比过去 7 天平均 × 1.5」 > 「死阈值 $100」（业务做大死阈值会失效）。

## 监控工具（按推荐度）

```
★ LangSmith       LangChain 官方，跟 LangGraph 无缝集成（收费）
★ Langfuse        开源 + 自托管，国内友好
  Datadog/NewRelic 公司已有就接，但对 trace 不友好
  print 日志       学习/个人项目够用
```

**对非程序员**：现在不用学，第 10 章项目里有需要 → 注册 Langfuse Cloud 5 分钟上手。**核心是懂概念**（trace + 3 类指标 + 告警分级），跟工程师能讨论需求就行。

# 📌 关键心智沉淀

```
1. 上线 = 安全 + 部署 + 监控 三件事，缺一不可

2. 安全先于性能，红色工具必须 Human-in-the-loop

3. 把 agent 包成 web 服务的 4 套路：
   逻辑分离 / 状态外挂 / 接口契约 / 生命周期端点

4. 3 类核心指标：钱（成本异常）/ 快（p95）/ 准（成功率 + 重提问率）

5. Trace 是 agent 监控的核心创新——没 trace 等于黑盒

6. 告警阈值要相对、要分级，不要"绝对值 + 一刀切"
```

# 🎓 给非程序员视角的总结

```
你不需要会写：
   - FastAPI 路由代码
   - Celery 异步队列
   - LangSmith / Langfuse 集成代码

你需要会跟工程师说清楚：
   ✅ 我们的 agent 是哪种部署形态（HTTP/SSE/后台）
   ✅ 工具要按 🟢🟡🔴 分级，红色必须人审
   ✅ 上线必须有 trace + 钱快准三类指标 + 分级告警
   ✅ 国内用户要域名备案，国外不用
   
这就是「产品视角的 agent 工程能力」——
比写代码的工程师更宏观，但比纯产品更懂技术。
```
